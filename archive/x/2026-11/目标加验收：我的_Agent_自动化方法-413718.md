# 目标加验收：我的 Agent 自动化方法

Lauren Tan 写了一份自动化入门指南，核心思路是：先讲清目标，再教 bot 怎么做。

说一点我跟她不一样的地方。

Lauren 自己很强，加上 Grok 模型可能还不够聪明，所以她把更多功夫花在教 Agent 做事上：把自己的最佳实践交给 Grok bot，让它像自己一样思考。

我觉得 AI 比我聪明，用的模型也不局限于 Grok，所以我更强调目标和验收，至于中间的步骤，不太干涉。

我的方法更像一个循环：目标 → 验收 → 改进，一轮一轮转下去。

1. 目标

告诉 AI 我想要什么。这一步谁都一样，必不可少。

2. 验收标准（可选）

告诉 AI 怎么自己检验结果好不好，这样它在把结果交给你之前，会先自己验收一遍。最好再给 Agent 配上验收用的工具，比如截图、网络检索、代码运行环境。

比如我做新闻发布自动化，一条重要的验收标准就是：动笔之前必须先做事实核查，确保内容真实、有出处。

有些任务还可以沉淀出测试集或者自动化测试代码，每次跑完自动验一遍。

3. 先跑起来再调整

目标讲清楚了，就可以先让 Agent 跑一遍看看。就像拿到一把枪，先朝靶子开一枪，打完就知道离靶心差多少、往哪边偏，接下来怎么调心里就有数了。

至于它具体是怎么执行的，不一定要看得很细，现在大部分任务 Agent 都做得挺好。不放心的话，看一看、指导一下也没问题。

调整结果才是最考验专业水准的地方。你自己得知道什么是好的，不然只能 AI 生成什么就接受什么，结果多半好不到哪去。

光看出来不好还不够，还得能准确地描述给 AI，让它知道往哪个方向改。

这样来回几次，结果才会慢慢稳定下来。但不管怎么说，先跑起来最重要，跑起来了才有东西可以优化。

4. 让它自己进化

Agent 有能力自我进化，前提是把经验教训记下来。现在的 Agent Harness 虽然都有记忆功能，但不一定会主动记录自动化任务里遇到的问题。

所以我通常从两个层面，让 Agent 自己提升任务的执行质量。

一个是把最佳实践沉淀成 Skill（包括工具）。比如我给 Agent 一个目标，来回打磨几次，它完成得很好。这时候如果就不管了，下次新开一个会话，记忆就没了；就算去翻历史会话，里面也有太多无关信息。不如趁热让它把这次的最佳实践做成 Skill。

另一个是让它主动记录执行过程中的经验教训，再回头改进 Skill 本身。

比如我做逆向任务，每一轮执行完都让 Agent 往 lessons.md 里记一笔：有教训就写下来，没有就跳过。然后让模型自己评估，要不要去优化 Skill 的说明和脚本。

这样一轮轮下来，Agent 干活就越来越熟练。

这种自我进化也有副作用：Skill 会越来越臃肿，所以要定期重构清理一下，这事交给 Agent 自己做就行。

每次重构完，记得把以前的测试集和自动化测试重新跑一遍，免得删掉不该删的东西。

Lauren 是把人的经验教给 Agent，我是定好目标和验收，让 Agent 自己跑、自己积累经验。模型越聪明，后一种越省心。
