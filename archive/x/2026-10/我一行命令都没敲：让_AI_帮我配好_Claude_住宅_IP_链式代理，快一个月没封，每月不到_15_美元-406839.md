再说过程：我一行命令都没敲。 从装代理到写 Clash 配置，全程是我告诉 AI 要什么效果，它直接上服务器帮我配好，我只负责验收。

网上很多教程会把配置一行行贴出来让你照着抄，我觉得这个思路已经不对了。现在是 AI 时代，还让人对着教程一条条抄命令，本身就是落后的做法。你真正需要知道的只有三件事：

要搭成什么样（架构）

为什么这么搭（原理）

怎么判断它真的搭好了（验收）

至于"怎么做"，交给 AI。所以这篇我不放任何命令和配置，只放每一步的目标、原因、给 AI 的提示词，以及验收标准。

丑话说在前面：这套只能降低风控概率，不能保证不封。Anthropic 的规则不公开，也会变，账号注册信息、付款方式、使用习惯都会影响结果。

整体架构：先看懂再动手

我手上两台 VPS，分工很明确：

Claude：本机 Clash Verge → DMIT（VLESS + Reality）→ Webshare 静态住宅 IP → Claude

ChatGPT / Grok / 支付：本机 → DMIT → 目标网站

YouTube / X / GitHub 等大流量：本机 → RackNerd（Hysteria2）→ 目标网站

[图片]

核心思路就一句：Claude 容易封，很大原因是它看到的出口是机房 IP。 让它看到一个固定的、美国的、家庭宽带的住宅 IP，而且长期不变。但国内直连住宅代理又慢又不稳，所以先用自己的 VPS 翻出去，再从 VPS 连住宅 IP，这就是链式代理.

这张架构图你自己要懂。AI 能帮你执行，但"要搭成什么样"得你来定。

全文分四部分：准备 → 服务器端 → 客户端 → 验证与维护，一共 8 步。

第一部分：准备

第 1 步：准备一个能上服务器的 AI 工具

整套活儿真正动手的都是 AI，所以第一件事是找一个能直接登上 VPS 的 AI 工具，让它自己装软件、改配置、看日志、排错，我只管提需求和验收。现在终端里跑的 AI 编程助手基本都行，在本机配好到 VPS 的 SSH 连接就可以。

给 AI 开服务器权限，我有几条习惯：

让它动手前先说计划，尤其是改网络、改端口、重启服务这类可能断线的操作，我看过点头再执行。

密码、UUID、密钥这些敏感信息，让它整理好只告诉我，别贴到公开的地方，截图发朋友圈前也记得打码。

生成的配置和密钥我自己存一份，换电脑、重装都用得上。

第 2 步：一次买齐三样东西

这一步要凑齐三样：一台线路好的主力机、一台跑大流量的副机、一个固定的美国住宅 IP。主力机线路稳，Claude 才不会动不动掉线；可好线路的流量贵，看视频这种事就得交给便宜机器。住宅 IP 则是整套方案的核心，机房 IP 在各种 IP 库里都标着 hosting，住宅 IP 看起来就是普通美国家庭用户。

第二部分：服务器端

第 3 步：DMIT 上搭 VLESS + Reality，再加一个 hy2

DMIT 是 Claude 链路的第一跳，我在上面放了一个走 443 端口的 VLESS + Reality 节点，伪装成访问 gateway.icloud.com。选 Reality 是因为它不需要自己的域名和证书，借用真实大站的 TLS 握手做伪装，别人探测你的服务器，看到的也是苹果的证书；443 又是最普通的 HTTPS 端口，一点都不显眼。顺手再加一个 Hysteria2 当备用，它走 UDP，哪天 TCP 线路抽风，ChatGPT 这些还能切过去应急。

第 4 步：RackNerd 上搭 Hysteria2

这台 RackNerd 我只拿来扛大流量，YouTube、X、GitHub 都走它。协议选 hy2，是因为它基于 UDP，在便宜机器、丢包多的线路上比 TCP 类协议猛得多，我这台实测 80 到 90 多 Mbps，YouTube 开 8K 都不卡。出口上我又加了一层 Cloudflare WARP，让一般网站看到的 IP 更干净；不过 Google/YouTube 走 WARP 反而容易慢，所以这两家让它直连。

第三部分：客户端

第 5 步：装 Clash Verge Rev

服务器那头好了，接下来是自己电脑上的客户端。我用 Clash Verge Rev，原因很简单：链式代理靠的是 mihomo 内核（Clash 的核心程序）里一个叫 dialer-proxy 的功能，中文一般叫"前置代理"。Clash Verge Rev 自带这个内核，Mac 和 Windows 都有，界面里还能直接看每条连接走了哪条链路，第 7 步验收全靠它。

装好后打开软件，在设置里能看到 mihomo 的内核版本就对了。这时候还没有配置，连不上外网是正常的，别慌。

手机也想用的话：iPhone 用 Shadowrocket 或 Stash（要美区 Apple ID 才能下），Android 用 FlClash 或 Clash Meta for Android。等第 6 步配置写好，让 AI 帮你转一份手机能导入的版本就行，重点是住宅链路那段别丢。

第 6 步：让 AI 生成配置（链式代理 + Claude 分组 + 分流）

这一步是把前面所有零件拼起来：Claude 走"DMIT → 住宅 IP"的链路，其他流量按用途分到两台机器。所谓链式代理（也就是 dialer-proxy 前置代理），就是连住宅代理之前先经过 DMIT 的节点，这样国内到 DMIT 这段是加密的 Reality，Claude 最终只看到住宅 IP。

分流这块，才是两台 VPS 的意义。说个真实数字：这个计费周期才过了二十来天，DMIT 已经跑了 837GB，额度是每月 1000GB，而且他这个额度是双向计费，那其实只有500GB的样子。CN2 GIA 好是真好，但 YouTube 一开 4K，一晚上几十个 G 就没了。所以我的原则是：

DMIT 只跑 Claude 链式、ChatGPT/Grok、支付这类"要稳、流量不大"的

RackNerd 扛 YouTube、X、GitHub 这类"要量不要命"的

第 7 步：验证，别凭感觉

这里可以看到Claude 和 ChatGPT、Grok 显示不同的出口，正好符合我的分流方案：Claude 用住宅出口，ChatGPT 和 Grok 用 DMIT 出口。

如果 Claude 显示成了 DMIT，就让 AI 查 Claude 组有没有选中住宅节点、相关域名有没有命中规则，以及 dialer-proxy 关联的节点名字是否一致。ChatGPT 或 Grok 走错出口，也按各自的分组查，别为了让结果好看，把整个测试网站统一塞进 Claude 组。

3. 注册、登录、付款都只走这条链

Claude 的注册、登录、日常使用都在住宅链路上完成，别今天走链路、明天图省事用别的节点登。给 Claude 付款的那几分钟，在 Clash 面板里把支付组手动切到住宅节点，付完再切回 DMIT，这样付款时看到的出口和平时是同一个 IP。

常见坑

住宅 IP 别换来换去。今天美国明天新加坡，比用机房 IP 还危险。买了就一直用这一个，除非它真被标记了。

地区、付款、IP 保持一致。IP 在美国，账号资料和付款卡尽量也对得上。

一号一 IP。住宅 IP 再干净，一个 IP 下挂七八个号也会出事。

dialer-proxy 名字差一个字就失效，而且不报错。差一个空格或 emoji 就链不上，直接用 DMIT 出口。所以每次改完配置都让 AI 核对一遍名字，再按第 7 步验一遍。

UDP 没放行、QUIC 漏网。hy2 连不上，十有八九是厂商后台的 UDP 端口没开；浏览器也可能走 UDP 443 绕过规则。这两条每次改完都让 AI 确认一下。

最后

总结一下：

国内 → DMIT：CN2 GIA + Reality，解决稳和不被墙

DMIT → 住宅 IP：让 Claude 看到家宽，不是机房

RackNerd hy2：好线路流量不够，便宜机器来扛

成本：DMIT 10.9 美元 + Webshare 约 4 美元，Claude 这条链路每月不到 15 美元；再加上 RackNerd（年付 21.99 美元，一个月不到 2 美元），全套每月 17 美元左右。

再强调一次，这套只是降低风险，不是免死金牌。

最后说回思路。这段时间我最大的感受不是"代理搭好了"，而是我已经不自己敲命令了。人的价值在于知道要什么、为什么、怎么验收，剩下的交给 AI，效率高，还不容易手滑。
