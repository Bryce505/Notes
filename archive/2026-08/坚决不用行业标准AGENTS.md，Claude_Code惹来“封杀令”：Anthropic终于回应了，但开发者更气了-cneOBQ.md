作者 | Tina

当所有 AI 编程工具都在向行业标准靠拢时，Anthropic 的 Claude Code 偏要特立独行。它拒绝支持已被超 6 万个开源项目采用的 AGENTS.md 格式，固执地守着自家 CLAUDE.md 不放。

这份“特立独行”终于踢到了铁板。全球电商巨头 Shopify 的 CEO Tobi Lütke 公开威胁：要么支持 AGENTS.md，要么在 Shopify 内部全面禁用 Claude Code。

一份文件引发的禁用风波

Shopify CEO Tobi Lütke 认为，Claude Code 拒绝读取 AGENTS.md，迫使大型研发团队承担了一笔本可避免的“复杂度税”。

“我正在考虑在 Shopify 禁用 Claude Code，直到他们改变主意，愿意读取 AGENTS.md、.agents/skills 等文件。”Lütke 在 X 上写道。

[图片]

这看起来只是一场围绕 AI 编程工具配置方式的小争议，但放到 Shopify 这样的大型研发组织里，一处格式差异很快就会演变成平台工程问题。

Shopify 有数千名开发者共同维护一个庞大的单体代码库（monorepo），使用的 AI 编程工具却不尽相同。每个智能体都需要根据当前处理的代码，读取相应目录中的项目指令。一旦某款工具没有读到与其他工具相同的指令，开发者使用的智能体就可能遵循不同的规则。

Lütke 随后在另一篇帖子中解释道：“AGENTS.md 和 CLAUDE.md 都会沿目录树递归生效。数千名开发者共同维护一个 monorepo，难免会有某个目录漏掉其中一份文件，结果就是一部分开发者用上了‘被切掉一块脑子’的智能体。”

[图片]

Shopify 已经通过自动化机制弥补了这种差异，但 Lütke 认为，公司的工程师原本就不该为此额外投入精力。

“我们用自动化解决了这个问题，但这是一笔愚蠢的复杂度税，原本根本不该付。”他写道。

近一年来，开发者一直在要求 Anthropic 支持 AGENTS.md， 其中，2025 年 8 月提交的主要功能请求已经获得近 5000 个 GitHub 用户点赞，成为 Claude Code 社区反响最强烈的兼容性诉求之一。然而，相关 issue 接连在没有充分回应社区质疑的情况下被关闭，“不予修复”成了 Anthropic 留给数千名开发者的答案。

[图片] 开发者随后把要求推进到大型代码库最需要的递归加载：让 Claude Code 自动查找根目录及各级子目录中的 AGENTS.md，按照距离当前代码最近的文件优先生效，同时显示本次任务究竟读取了哪些指令。这样一来，根目录可以保存全局规则，子项目再定义各自的构建命令、测试规范和操作边界，团队无需在整棵目录树中复制一套 CLAUDE.md。这项请求最终同样被关闭，并标记为“暂无计划”。

[图片]

直到 Shopify CEO Tobi Lütke 公开放话要在公司内部禁用 Claude Code，沉默近一年的 Anthropic 才终于作出回应。

为了兼容，开发者被逼写了多少“无用”脚本？

随着编程智能体的能力越来越强，工程团队也需要一种能够长期保存项目指令的方式。AGENTS.md 和 CLAUDE.md 等文件正是在这样的背景下出现的。

开发者可以把构建命令、测试要求和编码规范等内容直接写进代码仓库中的指令文件。智能体工作时会自动读取这些信息，无需开发者每次重新说明。麻烦在于，各家编程工具至今没有采用统一的文件格式。

OpenAI 于 2025 年 8 月推出 AGENTS.md，用于向编程智能体提供项目级指令。到当年 12 月，OpenAI 表示，已有超过 6 万个开源项目和智能体框架采用这种格式，支持它的工具包括 Codex、Cursor、Gemini CLI、GitHub Copilot、Jules 和 VS Code。此后，OpenAI 将这一格式移交给 Linux 基金会旗下的 Agentic AI Foundation。

Claude Code 走了另一条路。它使用 CLAUDE.md 保存项目指令，并且能够在处理代码时读取仓库不同目录中的 CLAUDE.md。它目前不会原生读取 AGENTS.md，虽然开发者已经多次要求 Anthropic 增加这项能力。

Anthropic 提供了一些变通方案，例如通过 CLAUDE.md 导入 AGENTS.md，或者为文件创建符号链接。

开发者 Ian Nuttall 就分享了一段颇为复杂的提示词，让 Claude 在 Mac 上搭建一套自动化兼容机制：递归查找所有 AGENTS.md，在同一目录创建指向它的 CLAUDE.md 符号链接；用 fswatch 持续监控新文件；设置 launchd 代理开机自动运行；再把生成的 CLAUDE.md 加入全局 Git 忽略列表，避免误提交。

这套方案看似解决了兼容问题，却恰好印证了 Lütke 所说的“复杂度税”——为了让 Claude Code 读取其他主流工具已经原生支持的 AGENTS.md，开发者还要额外维护查找脚本、文件监控、自动启动配置和 Git 配置，并且得确保这套机制在团队所有成员的机器上保持一致。

[图片] [图片]

但也不是所有人都能搞定这个事儿。有网友也尝试过很多方法让 Claude Code 读取 AGENTS.md 文件，Claude Code 却始终没有响应，最后他不得不转向 Cursor。

而且，在大型代码库中，团队还需要保证分散在不同目录、面向不同工具的指令始终保持同步。

因为在大型代码库里，项目指令可能分布在整棵目录树中，智能体处理不同位置的代码时，需要遵循对应目录下的不同要求。Claude Code 通过 CLAUDE.md 实现这一机制：当它处理某个目录中的代码时，会读取与该目录相关的指令文件。

这正是 Lütke 所举案例的关键。如果某个目录中存在供其他工具读取的 AGENTS.md，却没有为 Claude Code 准备对应的 CLAUDE.md，那么使用 Claude Code 的开发者就可能在缺少同等上下文的情况下工作。

Shopify 也并非唯一遇到这一问题的公司。一项针对 2926 个 GitHub 代码仓库的 2026 年研究 发现，上下文文件已经成为开发者向编程智能体提供指令的最常见方式，AGENTS.md 也已经被多种工具采用。

Shopify 已经构建了一套自动化机制来处理这种差异。随着企业把越来越多的编程智能体引入同一个代码仓库，如何确保所有工具读取相同的指令、遵循相同的规则，也将成为平台团队新增的一项工作。

争议升级：Anthropic 的回应激怒开发者

Claude Code 团队成员 Thariq 对此回应称，他们正在提高 Claude Code 的可定制性，未来将允许开发者更方便地使用 AGENTS.md，或者修改其他系统提示词。

[图片]

现阶段仍需在 CLAUDE.md 中写入 @AGENTS.md，由它导入 AGENTS.md。未来可能会简化这一步，但是否会像 Codex、Cursor 等工具一样默认识别 AGENTS.md，这条回复并没有说清楚。

他同时解释了 Anthropic 坚持现有方案的部分原因：团队认为不同模型需要的上下文和指令并不完全相同。

Thariq 此前透露，Anthropic 已经为最新一代 Claude 5 模型删掉了大约 80% 的 Claude Code 系统提示词，所以 Anthropic 更倾向于根据模型特性调整系统提示词、Skill 和 CLAUDE.md，而没有直接接受一套跨模型通用的项目指令。

一位开发者随即反驳，自己平时就会使用五种模型，代码仓库的其他贡献者使用的模型更多。如果每种模型都需要一份单独优化过的指令文件，一个项目难道要同时维护 17 份 AGENTS.md，并且随着模型每隔几周更新一次，持续重新评测和改写？

“没有人会这么做。”他认为，主流 Harness 的开发者可以在产品内部针对不同模型进行适配，就像 Claude Code 已经做的那样，但不应该把这笔维护成本转嫁给普通开发者。

按照“每种模型都要配备专属指令文件”的逻辑，仅仅使用 Claude 的团队就可能需要维护 CLAUDE_FABLE_5.md、CLAUDE_OPUS_5.md、CLAUDE_OPUS_4_8.md 等一系列文件。

每当模型更新，企业还要投入大量 token 重新评测，甚至安排一个团队专职维护这些 Markdown 文件。

[图片]

“Anthropic 再次拒绝遵循 AGENTS.md 等行业标准，并坚持认为 CLAUDE.md 需要与众不同。”

多位网友同样也认为，这纯属 Anthropic 的产品文化问题。Anthropic 拒绝遵循 AGENTS.md 这样的行业通用约定，坚持让 CLAUDE.md 保持特殊地位，传递出一种“只有我们知道最佳方案”的态度：OpenAI 的做法不对，开源社区的做法也不对，Anthropic 才知道模型应该如何获得指令。

[图片] [图片] [图片]

Anthropic 愿意开放更多定制能力，但允许用户自行定制与遵循行业标准是两件事。更合理的做法，是让 Claude Code 默认读取 AGENTS.md，同时把 CLAUDE.md 保留为需要特殊适配时的备用入口。

“我喜欢 Anthropic 的很多产品，尤其是 Fable。”这位网友最后写道，“但我希望他们能意识到，这里存在一种文化问题，而他们正在因此逐渐失去开发者的关注。”
