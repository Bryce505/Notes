## AI时代需要补的网络基础知识

- **摘要**：作者从自己"不学网络就处处被卡"的体验出发，把 AI 时代常用的网络概念串成一条线：IP 与 IPv4/IPv6、内网 IP 经 NAT/PAT/CGNAT 变成公网出口、回环地址；在外访问 NAS 的三种方案（端口映射+DDNS、内网穿透、Tailscale/ZeroTier 组网）；客户端/服务器/网站与请求响应模型；CPU、内存、硬盘、GPU 与 CDN；域名、URL、DNS 递归查询链路与公共 DNS 的六大好处；代理与 VPN 的原理差异（隧道 vs 转发、REALITY 伪装为何更抗封锁）、HTTP 代理与 SOCKS5、显式与透明代理；机房/住宅/移动/ISP IP 的风控差异与选型；节点命名、直连中转专线、流量倍率；最后落到 API、SSE 流式传输与限流/超时/重试的实战坑。整体是一份面向 AI 工具使用者的网络扫盲长文。
- **洞见**：
  - 科学上网能否稳定，关键不在"多一层加密"，而在流量能否被识别出代理特征，所以 VLESS+REALITY 这类伪装方案优于特征明显的 VPN 隧道。

  - 住宅 IP 不等于干净 IP，也不等于动态 IP；一个长期独享、无滥用记录的机房 IP 可能比被用滥的住宅代理更稳。
  - 在 AI 时代真正拉开差距的是能否用准确的术语向模型描述问题，而不是会不会让模型"用大白话解释"。
- **是否值得读**：概念覆盖密集且成体系，把 IP、DNS、代理、风控、API 串成一条可操作的认知链，并给出选型与排错方法，适合精读后当手册反复查。

- **摘要**：文章针对 2026 年国庆期间 Claude 大规模封号（含两年老号、刚充的 Max），拆解官方封禁规则并给出一套实操防封方案。作者引述 Anthropic 透明度中心数据：2026 上半年封禁 1140 万账号，申诉推翻率约十分之一；9 月威胁情报报告显示疑似不受支持地区的账号会被要求身份验证，只能用本人真实证件。核心主张是风控本质为多维打分系统，时区撕裂、WebRTC 泄漏、终端代理残留和退款退路比花大钱买家宽更关键。全文按环境、账号与支付、使用行为、Claude Code 本机设置四层防线展开，附时区改台北步骤、ipinfo/browserleaks 自检命令、TUN 模式配置、11 步最低稳法清单与退款申诉路径。文末含住宅 IP 服务与新加坡卡两处返利推广。
- **洞见**：
  - 风控是多维打分而非单点判定，时区撕裂、WebRTC 泄漏、ANTHROPIC_BASE_URL 残留往往比 IP 类型更致命。
  - 环境的关键词是「固定」而非「纯净」——设备和出口长期不变，比反复切换更干净的节点更保号。
  - 支付渠道直接决定封号后的损失：官方条款明写不退款，走 App Store 内购至少还有一次向苹果申诉的机会。
  - 养主力号不要用共享 IP 或共享账号，同一出口里只要有人蒸馏或接第三方客户端，其他人会被连坐。
- **是否值得读**：操作清单密集、标注了官方条款与数据出处，具备可执行价值，但夹杂大量社区传闻和两处返利推广，需要自行甄别后使用。
