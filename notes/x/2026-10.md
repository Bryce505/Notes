- **摘要**：作者结合入职大厂两个月的 Agent 开发实践，分享如何用 Codex、Astra、Claude 等工具和轻量 Skill/Prompt 提升开发效率。核心做法是少写重型流程，改用第一性原理、对抗性审查、消融实验、奥卡姆剃刀、高内聚低耦合等“思维快捷键”；工作流上先对齐需求并沉淀 Spec/Context，再拆分 Issue 并行实现，并用 Agent 友好的端到端测试和聚焦高风险的 Review 保底。结论是开发瓶颈已转向人的审查速度，Harness 需要同时提供上下文、执行环境和判断依据，工作流也要随模型迭代做减法。
- **洞见**：
  - 模型变强后，重型 Skill 和工作流可能变成噪声，应定期删减约束：简单任务直接做，复杂任务再加规划、拆分和交叉审查。

  - Agent 友好的端到端环境——一键启动、真实业务操作、只读 DB/日志、CLI 与 Skill 复用——是让 AI 代码可交付的关键基础设施。
  - AI 开发真正的瓶颈是人的理解、判断和 Review 速度，而非代码生成速度；Review 应聚焦验收标准、业务路径和高风险机制。
- **是否值得读**：信息密度高，给出可直接复用的 Prompt、工作流、端到端测试与 Review 方法，并对 Harness 和工作流“做减法”有独到判断，值得精读。

- **优先级**：高 ｜ **状态**：未读
- **关键词**：网络基础 / NAT / DNS / 代理与VPN / IP类型 / AI API
- **摘要**：作者从自己"不学网络就处处被卡"的体验出发，把 AI 时代常用的网络概念串成一条线：IP 与 IPv4/IPv6、内网 IP 经 NAT/PAT/CGNAT 变成公网出口、回环地址；在外访问 NAS 的三种方案（端口映射+DDNS、内网穿透、Tailscale/ZeroTier 组网）；客户端/服务器/网站与请求响应模型；CPU、内存、硬盘、GPU 与 CDN；域名、URL、DNS 递归查询链路与公共 DNS 的六大好处；代理与 VPN 的原理差异（隧道 vs 转发、REALITY 伪装为何更抗封锁）、HTTP 代理与 SOCKS5、显式与透明代理；机房/住宅/移动/ISP IP 的风控差异与选型；节点命名、直连中转专线、流量倍率；最后落到 API、SSE 流式传输与限流/超时/重试的实战坑。整体是一份面向 AI 工具使用者的网络扫盲长文。
- **洞见**：
  - 科学上网能否稳定，关键不在"多一层加密"，而在流量能否被识别出代理特征，所以 VLESS+REALITY 这类伪装方案优于特征明显的 VPN 隧道。
  - VPN 是网卡层面的加密隧道、整机全走；代理是应用/规则层面的转发，可按规则分流，二者不是同一个东西也不是替代关系。
  - 住宅 IP 不等于干净 IP，也不等于动态 IP；一个长期独享、无滥用记录的机房 IP 可能比被用滥的住宅代理更稳。
  - 在 AI 时代真正拉开差距的是能否用准确的术语向模型描述问题，而不是会不会让模型"用大白话解释"。
- **是否值得读**：概念覆盖密集且成体系，把 IP、DNS、代理、风控、API 串成一条可操作的认知链，并给出选型与排错方法，适合精读后当手册反复查。

- **摘要**：作者被封过一次号后逆向研究Claude风控，认为封号不是单一原因，而是上百个指标共同决定账号权重，权重跌破阈值才触发封禁，所以同样的行为有人被封有人无事。他分析Claude对个人（尤其中文）用户严苛的动机：八成收入来自企业、算力紧张、创始人立场。随后拆解四个权重最大的因素：IP（住宅/移动网络优于机房，必须独享，否则受连坐机制牵连，并逐家点评十余个供应商的踩坑经验与真实住宅IP的价格门槛）、订阅渠道（美区礼品卡、Google Play绑卡、U卡号段黑名单）、地理位置泄露（WebRTC、DNS、QUIC与运营商锁Resolver）、使用习惯（只用网页版和Claude Code、固定日本IP、专用Chrome profile等十一项浏览器设置、全局TUN、被封设备彻底清理）。结论：靠几十项措施叠加维持高权重，三个账号已存活八个多月。

  - 地理位置泄露（WebRTC、DNS、QUIC、浏览器指纹）比IP本身更容易被忽视，用全局TUN加专用浏览器profile比规则模式更安全。
