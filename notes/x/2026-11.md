## 为了用上 Claude，这是我所做的（干巴版）
- **剪藏**：2026-11-02 05:53 ｜ **发布**：2026-06-04
- **优先级**：中 ｜ **状态**：未读
- **关键词**：Claude Code / 静态住宅IP / 链式代理 / 账号风控 / 智能分流 / 订阅支付
- **摘要**：面向国内用户的 Claude 及 Claude Code 上手指南，核心论点是「封号主要取决于网络与支付环境，操作技巧并不是主因」。作者提出三阶段风控模型（注册、订阅、使用），称约 90% 的封号发生在订阅支付环节，因此关键是用静态住宅 IP（ISP 显示为 AT&T 等家庭运营商）替代机房 IP，并通过「机场节点 + 住宅 IP」的链式代理串联。教程分步给出小火箭与 V2rayN 的配置方法、用 ping0.cc/ipinfo.io 验证 IP 的五项检测、Gmail 注册与 HeroSMS 接码、三种低风险订阅路径（第三方订阅、美区 Apple ID 礼品卡、Google Pay 双币卡）对比，以及养号节奏与雷区清单。进阶部分用 RULE-SET 规则集做智能分流，让 Claude 域名自动走住宅 IP。
- **洞见**：
  - 封号风险并不均匀：注册只是低风险环节，真正触发风控的是订阅支付那一刻，所以「一充值就被封」是常态而非意外。
  - 决定账号存活的关键是 IP 的 ISP 属性，地理位置本身并不是决定因素：住宅 IP 的 ISP 显示为家庭运营商，机房 IP 则会被风控直接识别为异常。
  - 链式代理与规则集分流把「每次手动切节点」变成一次性配置，自动化能消除因忘切节点而导致的封号。
  - 养号节奏本身就是风控策略：免费→Pro→Max 逐级递进、额度不用满、单设备使用，模拟的其实是正常用户的消费曲线。
- **是否值得读**：内容系统且可操作（风控模型、链式代理、分流规则集都有具体步骤），但夹带多个带邀请码的服务商推广，且属二次整合教程，非原创洞见。

## 机场＋台湾静态IP稳定用上Claude的配置指南
- **剪藏**：2026-11-01 22:10 ｜ **发布**：2026-11-01
- **优先级**：中 ｜ **状态**：未读
- **关键词**：Claude 使用教程 / 链式代理 / 静态 IP / 网络代理配置 / 谷歌商店订阅
- **摘要**：作者分享自己在中国大陆使用 Claude 的整套办法：机场出境后，接入一个台湾独享静态 IP，做链式代理，让 Claude 只看到这个固定出口；再配合谷歌邮箱、指纹浏览器、系统时区和谷歌商店付款。他解释了原理：机场是多人共用 IP，一旦被封换节点也没用；静态 IP 独享但无法直接出网，须挂在机场后面，且地区须与机场一致以免高延迟（实测台湾 44 毫秒、美国 300 多毫秒）。文中给出 1024proxy 采购、用 Clash Verge Rev 配置、用 ip.net.coffee 验证、买或自注册谷歌号时注意更换密码，以及绑定国内 VISA 卡、填美国免税州账单地址。作者也承认，虚拟标注为“家庭IP”的 IP 被查出来是机房 IP，通过谷歌商店多付 50 美元相当于为可能的封号买保险，且全程不保证不封号、不保证不亏钱。
- **洞见**：
  - 机场共享 IP 一旦被封，换别的节点也没用；真正能防封的是独享且固定的出口 IP。
  - 光有静态 IP 不够，它本身出不了海；必须接在机场后面做链式代理，且两边选同一地区，否则延迟从几十毫秒涨到几百毫秒。
  - 封号不只取决于 IP，还包括时区、浏览器指纹等环境一致性；IP 只是其中一小部分。
  - 用谷歌商店订阅比官网贵约 50 美元，但被封后可向谷歌申诉退款，相当于为风险买保险。
- **是否值得读**：属步骤具体、可直接照做的操作指南，但夹带返利链接、依赖灰色服务，且作者自认效果与合规风险都不保证，适合有需要时参考而非精读。
